JavaScript 事件循环机制详解

2026-07-30 阅读约 — 分钟 JavaScript异步

面试高频题：setTimeout(fn, 0) 会立即执行吗？Promise 的微任务和 setTimeout 的宏任务谁先执行？答案都在「事件循环」里。

单线程与调用栈

JavaScript 是单线程的：同一时刻只能做一件事。代码进入内存后，由 调用栈（Call Stack）逐一执行，后进先出。栈空了才轮到异步任务。

宏任务与微任务

异步任务分为两类，执行优先级不同：

  • 宏任务（Macro-task）：setTimeout、setInterval、I/O、UI 渲染
  • 微任务（Micro-task）：Promise.then、queueMicrotask、nextTick

调度规则一句话：每执行完一个宏任务，就清空所有的微任务队列，再开始下一个宏任务。

经典例题

console.log('同步1');

setTimeout(() => {
  console.log('宏任务');
}, 0);

Promise.resolve()
  .then(() => console.log('微任务1'))
  .then(() => console.log('微任务2'));

console.log('同步2');

输出顺序：

  1. 同步1 —— 同步代码先执行
  2. 同步2 —— 依次执行
  3. 微任务1、微任务2 —— 本次宏任务结束后，微任务队列按序清空，注意 .then 链是依次注册依次执行
  4. 宏任务 —— 然后才轮到回调队列里的 setTimeout

所以 setTimeout(fn, 0) 只是「至少要等 0 毫秒」，并不保证立即执行——它前面还有一整条微任务队列等着清空。

完整的调度流程

可以用下面这段伪代码概括整件事：

while (事件循环继续) {
  执行一个宏任务;          /* 同步代码也是宏任务的一部分 */
  清空所有微任务;          /* 微任务里注册的新微任务也会被执行 */
  必要时渲染 UI;           /* 执行 render */
}

这也解释了为什么微任务总能在下一帧渲染前跑完——所以用它做 DOM 更新不会闪烁中间状态。

小结

  • 同步代码永远先跑完，才轮到异步
  • 微任务比宏任务优先，「宏任务之间」是微任务的舞台
  • setTimeout(fn, 0) 不等于立即执行，只代表加入宏任务队列

理解这个模型之后，无论题目怎么变，把每一步标注进「宏任务 / 微任务 / 同步」三列，答案自然就出来了。
